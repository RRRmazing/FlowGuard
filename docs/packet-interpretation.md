# 报文解读

在报文工作台选择一条记录，右下角按“报文用途、关键字段及含义、报文结构、网络与链路信息、解析情况”展示当前报文。内容超过区域高度时向下滚动，也可以拖动分隔条扩大详情区域。实时采集与 PCAP 分页使用同一个解读函数。

- ARP：请求或应答的作用、ARP 载荷中的发送方和目标 IP/MAC，以及以太网地址。载荷地址与以太网头地址分别标明，不混用。
- TCP：标志位含义、原始序列号、有效确认号、未缩放的窗口原始值、首部长度和选项字段。只有完整解析且未分片时才从 IP 长度推导 TCP 载荷长度；IPv6 扣除扩展首部。
- UDP：端口、包含首部的声明长度、扣除 8 字节首部后的声明载荷长度、校验和字段。声明长度不代表所有字节都已捕获。
- ICMP/ICMPv6：类型、代码、回声请求与应答、标识符和序号，以及常见不可达、超时通知的含义。
- DNS：查询或响应、事务 ID、操作码、响应码、AA/TC/RD/RA 标志、首个问题名称与类型和各类记录数量。当前解析器未展开回答记录内容，不能将回答数量当作已解析的答案。
- IPv4/IPv6：TTL/Hop Limit、DSCP/ECN、分片、IPv6 扩展首部，以及 VLAN 和链路地址。

解读依据 `ParsedPacket` 已有字段生成，不再次读取文件、不维护连接历史，也不改变图表与预警统计。缺失字段不补造数值。解析完整、抓包未截断、校验和正确和流量正常是不同概念：当前只展示校验和字段，不执行校验验证；不根据单包判定握手成功、重传或攻击。

本阶段完善右下角文字解读，保留左下协议树。原始字节页签及字段到字节的联动尚未实现。

验证方式：使用 CMake 标准构建后运行 `ctest --test-dir build/windows-msvc -R "packet_interpretation|stage3_gui_integration" --output-on-failure`（需配置 Qt/Npcap 运行时）。单元测试覆盖固定协议样本、分片、截断、IPv6 扩展首部及 DNS 错误与截短响应；界面测试验证选择 TCP/ARP 后解读随之切换。
