# 报文保存流程与验收

当前更新：新用户使用系统文档目录下 FlowGuard/Logs 和 FlowGuard/Captures，有效时直接启动，不再要求首次确认；现有自选位置迁移保留。分段保存、PCAP分页、预警与图表交互保持原有流程。最新验证见 [融合验收记录](integration-acceptance.md)。

本说明覆盖早期“先采集、先选文件位置、结束时直接关闭”的界面约定。后台仍使用经典 PCAP，保存原始字节及捕获时间、捕获/原始长度；显示筛选和界面缓存不影响保存范围，BPF 与截取长度仍决定采集内容。

## 操作与状态

每次点击“开始采集”，统一弹出两个直接按钮：“立即开始保存报文”和“暂不开始保存报文”。点击即按对应方式开始；即使已提前开启保存等待，也以这次选择为准。关闭弹窗不开始采集、不创建文件，保留已有结果和原等待状态。已有分析结果会被新采集替换的提示合并在同一小窗口中，不再连续确认。

| 场景 | 按钮和行为 |
| --- | --- |
| 实时采集准备状态 | 可点“开始保存报文”，变为“取消保存等待”，显示“等待采集”；此时不创建 PCAP 文件 |
| 已开启等待，点击开始采集 | 仍弹出两个选项；本次选“立即开始保存报文”才从第一包写入，选“暂不”则取消等待并开始采集 |
| 采集中开启 | 从后台接受启用命令后的后续处理包开始写入，过去未保存的原始报文不能补回 |
| 点击结束保存 | 后台关闭并刷新 writer，再弹保存窗口；实时采集继续 |
| 点击停止采集 | 先停止并排空采集队列，再关闭保存并弹窗 |
| 正常关闭窗口 | 有记录则先走停止和最终保存流程，完成后退出；取消保存窗口会丢弃本段并继续退出 |
| 没有写入报文 | 不弹保存窗口，清理可能存在的空 PCAP 头文件，显示“没有可保存的报文” |
| 成功打开 PCAP | 取消零报文保存等待，保存按钮置灰；文件分析期间不提供保存 |
| 取消打开或文件打开失败 | 保留原来的保存等待 |
| 分析完成后开始实时采集 | 直接点“开始采集”，在小窗口选择是否同时保存，无需额外准备操作 |

每段保存独立，不跨输入来源恢复开关。文件分析模式下仍可选择下一次采集的网卡，并显式进入实时准备状态；这不会立即清空现有分析结果，真正开始新会话时遵循原有确认流程。

## 用户选择目录与正式保存

已有有效配置（包括将来安装向导写入的配置）直接使用；直接启动且无配置时自动创建文档目录下 FlowGuard/Logs 与 FlowGuard/Captures，不再弹出首次确认窗口。需要更改时使用“保存设置 → 数据保存位置…”，目录失效或配置出错时才自动提示处理。系统文档位置通过 Qt 获取，不拼接固定盘符。已有自选目录优先保留，不强制搬运历史 PCAP。用户显式清空某一项仍表示不启用它。

配置统一放在当前用户应用数据目录的 `FlowGuard/storage.ini`，不再写安装目录。优先使用新配置，再读取旧版程序旁 INI，最后兼容旧用户设置中的 `pcap/defaultDirectory`；新配置中的空值也优先，不会被旧值覆盖。新用户默认目录自动创建，失效的旧自选目录不自动重建或换盘。每次保存前检查目录存在、可写、磁盘可用与至少 1 MiB 剩余空间。采集中目录无效时，可以打开设置纠正后开始保存，采集继续进行；当前已在保存的一段期间不允许切换目录。

日志初始化失败时会关闭部分打开的文件并清空失败的活动路径，保留错误说明及可能已生成的文件。用户改选有效目录后可在同一窗口立即重试，旧错误不会带入新记录；已正常开始的日志修改目录仍在下次启动生效。

日志未设置时资源采样继续在界面显示，但不写日志。首次选择日志目录立即开始新记录；已记录后变更目录在下次启动生效。测试和管理员可显式提供 `FLOWGUARD_LOG_ROOT`，不构成程序自动指定目录。

等待时不建立文件；开始实际采集时准备目录，后台第一次写入时创建 `.recording-随机唯一编号.pcap`，持续写盘，不把整段报文留在内存。未保存时可在采集中修改目录，已有保存段须先结束；本段始终在开始时选定的目录写入。

结束窗口默认进入本段记录目录，建议名为：

```text
2026-11-22_14-30-00-123_至_2026-11-22_14-45-00-456.pcap
```

时间取实际已写入报文的首末捕获时间，包含毫秒，跨天保留两个日期；等待时间不计入。用户可改名、改目录，已有同名目标由标准保存窗口确认是否替换。

- 直接确认同一磁盘的新文件：后台重命名临时文件。
- 选择其他磁盘或确认替换：后台流式复制至 QSaveFile，提交成功后再删除原临时文件。转存期间相关控制禁用，界面事件循环仍运行。
- 点击“取消并丢弃”：删除本段临时文件，不创建待保存记录；不会删除其他正式 PCAP。
- 写入、关闭、转存或删除失败：明确提示错误和原文件位置；转存失败不删除原记录。若文件创建本身失败，会提示未创建成功，不声称已有可恢复数据。

单段仍沿用原有 1 GiB 写入上限。触及上限或磁盘写入错误会停止该段写入、保留现场并提示；采集分析继续。异常退出可能留下 `.recording-*.pcap`，不自动删除，可到该段目录手动检查；末尾写入失败的文件可能需要恢复，不能保证完整。

## 后台接口

ProcessingSnapshot 增加 `savedSegmentPackets`、`savedFirstTimestamp`、`savedLastTimestamp`，记录本段成功写入的数据；原 `savedPackets` 仍是会话累计，不因分段结束清零。

`ProcessingSession::finishSaving()` 只能由控制线程调用，等待停止保存命令被处理且 writer 关闭后返回。界面不根据一次轮询的布尔值猜测文件已关闭。后台原有直接写入指定路径的接口保留，供命令行验证和既有测试使用；用户界面中的 PCAP 分析保存入口禁用。

## 用户验收

PCAP 打开入口统一为“文件 → 打开 PCAP…”或 Ctrl+O，工具栏不再重复显示打开按钮。

按 README 的开发运行环境启动新构建的程序，建议先在“保存设置”中选择一个便于检查的测试文件夹。

1. 启动后先点保存，确认“等待采集”且目录没有新增 PCAP。再次点击可取消等待。
2. 再开启等待，然后打开测试 PCAP，确认等待被取消且保存按钮置灰。尝试打开不存在的文件时，原等待应保留。
3. 在文件分析结束后直接点击“开始采集”，选择“立即开始保存报文”，产生正常网络流量后结束保存。另测提前开启等待后选择“暂不开始保存报文”，本次应只采集、不记录。
4. 检查弹窗默认目录、时间段名称和“取消并丢弃”文案。确认保存后，重新导入该文件，核对报文和时间；采集期间结束保存不应自动停止采集。
5. 再记录一段并取消弹窗，确认临时文件已删除。无流量时结束不弹保存窗口。
6. 尝试停止采集及关闭窗口，确认有数据的保存段会先完成最终处理。

自动验证入口为标准 CMake/CTest。新增 `recording_workflow` 使用自有 localhost UDP 报文，检查提前开启、第一包、分段、最终确认、取消、零报文、停止、关闭、启动失败、文件模式和转存失败。测试采用独立临时目录及独立用户设置位置，不修改真实默认目录或桌面。

本轮不提交、推送或合并，待用户人工验收。实际跨磁盘大文件耗时和磁盘故障场景仍需专项验证。

## 本轮验证证据

- MSVC Release 构建通过，差异空白检查通过。
- 完整 CTest 20/20 通过，耗时 19.83 秒，含现有预警、解析、存储、图表支持及真实 Npcap 回环测试。
- 追加窗口关闭收尾场景后，保存专项再次通过，共 72 项检查。所有流量发往测试创建的 localhost UDP 接收端。
- 提前开启记录后，保存文件重读包数与该采集会话处理包数一致，包含第一包；结束保存后采集仍处于运行状态。
- 用户设置测试使用独立 INI 目录，保存/删除/失败测试均使用测试自己创建的目录，没有修改真实桌面默认目录。
- 构建日志 `build/recording-build.log`；完整测试 `build/recording-ctest.log`；追加收尾验证 `build/recording-close-test.log`。
