FlowGuard 流量哨兵使用指南

适用于本地验收版，2026年11月22日。本文对应当前软件菜单及功能；用浏览器打开即可阅读，也可以按 Ctrl+P 打印或导出 PDF。

保存位置 · 实时采集 · 筛选与详情 · 图表 · 保存与回读 · 20分钟验收

先选择保存目录，再决定保存方式。全程保存：勾选“从采集开始保存” → 开始采集 → 停止。中途保存：取消勾选 → 开始采集 → 在需要的时刻点击“保存后续报文” → 停止。点击保存时不会再弹出路径选择窗口。两种方式都可直接打开保存的PCAP，或停止后另行导出副本。

1. 先选择保存到哪个盘

  1. 在未采集时，点击主界面的选择保存位置…。顶部“文件 → 保存位置…”和资源监控页的“设置保存位置…”也可使用。
  2. 运行日志目录建议选择 E:\FlowGuard数据\运行日志，存放 CPU、内存、运行事件等记录。
  3. 报文保存及默认导出目录建议选择 E:\FlowGuard数据\抓包。主界面会一直显示目录。每次采集自动生成带时间和随机标识的新PCAP文件名，避免覆盖旧数据。
  4. 点击“保存”。软件会检查目录是否可创建、可写，并记住设置；路径不必预先存在，可以手动输入完整路径。
  5. 正常退出并重新打开同一份程序，日志新位置在重启后生效。资源监控页显示“本次日志”的实际路径，可检查盘符。

报文目录对下一次采集立即生效，日志目录需要重启生效。设置保存在程序旁的 data/storage.ini，不会写入 C 盘注册表。当前程序位于 E 盘，默认日志和报文也在 E 盘。环境变量 FLOWGUARD_LOG_ROOT 若存在，会覆盖日志设置；资源页显示的本次实际路径为准。

采集中不能换目录，防止保存时再选路径产生漏存时段。需要换盘请先停止。开始前会检查预选目录是否可写及磁盘空间；路径未通过检查时不会启动采集。文件从启用保存后第一包起写入，不会因设置了目录就提前生成空文件。

2. 开始、停止和更换网卡

  1. 网卡下拉框选择实际联网的 WLAN（无线）或 Ethernet（有线），不要仅凭“已连接”判断；VPN、虚拟机网卡可能也显示已连接。没有数据时先检查网卡是否选对。
  2. 第一次测试让捕获过滤 BPF 留空，截取长度保持 65535，混杂模式可不勾选。
  3. 点击开始采集，正常浏览网页或使用自己的联网应用，观察累计报文和流量增加。采集无需一直停留在报文页。
  4. 点击停止会结束采集并关闭PCAP文件，保留本次列表与统计。文件已在预选目录，不必再次导出才算保存。可点“导出 PCAP…”另存副本；“打开已保存 PCAP”可直接读取。新会话替换列表与统计，但不删除此前的文件。

采集中网卡、BPF 和截取长度会锁定。混杂模式不保证能看到交换网络中其他电脑的全部流量。底栏“本次采集时长”随采集增加，停止后冻结，重开会话后归零。

3. 筛选和查看报文

功能怎么用会影响什么
捕获过滤 BPF开始前填写，例如 tcp、udp 或 udp or tcp。首次验收留空。进入程序的报文范围；因此影响采集、统计和保存。
显示筛选在报文页选协议，可输入完整源/目的 IP 或端口，然后点“应用”。多个条件共同生效；点“重置”清除。只改变列表显示，不改变会话累计统计和保存内容。
报文详情树点击列表中一条报文，查看下方协议字段，可展开 Ethernet、IPv4/IPv6、TCP/UDP、DNS 等节点。查看该报文的字段。异常或截短报文只能展示安全取得的字段。

TCP 可查看序列号、确认号、SYN/ACK 等标志、窗口和校验和；IPv4 可查看总长度、标识、分片、TTL；IPv6 可查看流标签、负载长度、Hop Limit。校验和是捕获值，不表示软件验证过正确性；选项以原始字节展示。

实时采集列表只保留最近2000条，旧记录淘汰不等于采集或保存丢包。打开PCAP文件读取完成后则提供完整分页：默认显示第1页，从文件第1包开始；用“首页 / 上一页 / 下一页 / 末页”及页码跳转查看全部报文，每页最多2000条，不会永久丢弃文件前面的记录。文件模式的显示筛选覆盖整个文件，并重新回到筛选结果第1页；实时模式的筛选只针对最近的记录。索引或翻页时显示“处理中”，大文件或重新筛选需要等待。

4. 看懂统计分析页

点击左侧统计分析，先看顶部协议汇总统计表，再向下滚动查看八张图。切换显示筛选不会改变这些会话统计。

表或图含义与核对方法
协议汇总表各协议会话累计包数及占总包数比例。网络分类 IPv4+IPv6+ARP+Other 应等于总包数；TCP/UDP/ICMP/DNS 跨层重叠，不可把所有行相加当总包数。
长度频次折线图各原始报文长度出现的次数。大于65535字节的长度合并到标记65536的桶。
长度三区间柱状图≤46 B、47–1500 B、>1500 B 三组；三组累计数应等于总包数。
网络分类柱状图、网络占比图IPv4、IPv6、其他；这里的“其他”包含 ARP，而汇总表把 ARP 单独列出。
TCP / UDP / ARP 柱状图这三类的累计数量，并不涵盖所有报文。
DNS 报文区间占比曲线每个时间区间 DNS 包数÷该区间全部包数。加密 DNS 可能无法识别，因此始终为零不一定是故障。
包速率、字节速率曲线随捕获时间变化的 pkt/s 和 KiB/s。屏幕保留有界时间窗口，不能把图的横轴当作整个软件的运行时长。

IPv6、ARP、DNS 没有数据可能是当前网络没产生相应报文。可用固定样本覆盖这些情况，不要仅凭某根柱子为零判断程序失效。

图表读数：所有折线图（包括CPU、内存）都支持采样点吸附、定位线和高对比提示卡；鼠标不必精确碰到细线，X轴附近也能读取。低值曲线按当前数据自动缩放，提示中的单位及数值仍是真实值。柱状图在对应分类区域内悬停即可查看包数和占本图所列类别的比例，零高度柱也可读取；饼图在扇区悬停时高亮，并显示类别、包数和占比。提示随定时刷新更新，移开后隐藏。不同图或不同时刻的自动纵轴范围可能不同，请比较标注数值，不要只比较曲线高度。

5. 全程保存、中途保存与停止后导出

想保存什么采集前采集中停止后核对
本次全程报文选好目录，勾选从采集开始保存（默认勾选）。点开始采集即从第一包写入，无需再点击保存按钮。无保存错误时，已保存数应等于本次采集总数。
某个时间点之后的报文选好目录，取消从采集开始保存。先采集观察，需要时点击保存后续报文，立即提交写入预选文件的请求，不再选路径。待状态确认后，后续处理的报文持续写入，直到停止采集。已保存数应小于采集总数；开启前的报文不补存。

主界面显示本次实际PCAP完整路径、累计采集数及实际保存数。“正在保存报文”表示保存已开启，不需要重复点击。两种方式每次采集各使用一个文件；若要另起一段，停止后再开始新会话。软件及操作系统有正常调度延迟，不承诺鼠标点击与网卡时间戳完全相同的零延迟边界；操作及保存请求的实际确认点记录在运行日志中，不存在选择文件窗口造成的数秒等待。

  1. 点停止并等待操作完成，PCAP文件即关闭并写完；记下实际保存数。
  2. 点打开报文目录直接找到文件。需要另存一份时点导出 PCAP…，选择其他盘和新文件名；它复制的是本次实际保存内容，不会补齐中途保存前的报文，也不受显示筛选影响。
  3. 先截图保留统计，再点打开已保存 PCAP由本软件重新读取。导入建立新分析会话，之前统计会被替换。
  4. 重读后的累计包数应等于该文件实际保存数，不要与中途保存模式的整场采集总数混淆。文件内重新从1编号，中途保存的第一包也是文件第1包；不沿用原采集会话编号。比如保存2600包，第一页是1–2000，第二页是2001–2600，翻页后连续编号；有筛选时显示各报文原本在文件里的序号。

单个保存文件上限为16 GiB，并按启动时可用空间预留256 MiB。达到上限或写入失败会报错，导出副本禁用，不能当作完整结果；原文件保留供排查。大流量长测注意磁盘容量。已有导出目标不会覆盖，另存副本需额外空间。支持经典PCAP，暂不支持PCAPNG；按时间回放支持倍速及暂停/继续/停止。旧版未保存的原始报文无法补回。

6. 资源监控与日志

点击资源监控，查看 CPU、内存、I/O、驱动丢弃、已保存原始报文数和 CPU/内存曲线。全程保存时保存数跟随总数增长；中途保存只统计开启后的部分。CPU 是占整机能力的比例；I/O 为整个进程累计读写量，不等于 PCAP 文件大小。短期内存增长不能单独证明内存泄漏。

点击打开运行日志目录可以找到本次记录。每次启动会新建一个运行子目录：

文件作用
run.json启动时间、版本、程序哈希、运行环境。
resources.csv每秒 CPU、内存、处理/保存数量、队列、丢弃和界面延迟，可供测试后分析。
events.jsonl开始、停止、保存等操作和错误事件。
result.json正常退出后才写入的收尾记录。采集停止而软件未退出时，没有这个文件是正常的。

7. 你来操作的20分钟验收流程

先设置 E 盘保存位置并重开软件，再开始计时。保持软件连续打开，停止/重开采集会话如实记录。

时间操作通过表现 / 留证据
0–2分钟打开仓库中的 tests/data/stage1-protocols.pcap，选“快速导入分析”；检查 IPv4、IPv6、TCP、UDP、ARP、DNS 和字段树。固定样本累计 18包、1156原始字节。拍一张展开 TCP 或 IPv6 字段的截图。
2–4分钟检查协议汇总表、八张图；试选TCP显示筛选、错误IP、重置。错误输入有说明且保留旧筛选；重置恢复列表；总包数和会话统计不随显示筛选改变。截图统计表及主要图表。
4–6分钟选择实际联网网卡，BPF留空，选好 E 盘目录，勾选“从采集开始保存”并开始。累计包数和保存数增加、PCAP路径在目标盘、无红色错误提示。
6–12分钟正常使用网络，在报文/统计/资源页切换，记录CPU、内存及响应。随后停止、截图、打开已保存PCAP。图表正常更新；重读数等于这次全程保存数及采集总数。记录真实丢包及卡顿。
12–16分钟取消“从采集开始保存”，开启新采集，等数百包后点击“保存后续报文”，继续使用网络。开启前已保存数为0；点击不弹路径窗口；开启后保存数增长，实际路径始终可见。
16–18分钟停止，记下总数和保存数。可另行导出副本，再点“打开已保存 PCAP”重新分析。重读数等于实际保存数；中途保存时少于整场采集总数。超过2000包仍应完整读取计入统计。
18–20分钟检查本次实际日志目录；记录问题，正常退出，确认result.json存在。截图与日志都来自本次真实运行，记录成功项、失败项和未覆盖项。

这轮20分钟是功能与短时稳定性检查，不能代替课程要求的至少24小时连续运行证据。当前基础功能、统计表、八图、保存回读、过滤及资源记录都有实现；人工排版、真实20分钟结果和正式长测需分别确认。攻击检测/SYN洪泛告警不在当前版本功能范围内。

8. 遇到问题怎么定位

  • 没有报文：检查网卡、BPF、显示筛选；生成正常网络流量，必要时停止后换实际 WLAN/Ethernet 再试。
  • 不能设置目录：先停止采集或回放；使用完整路径，检查目录权限及磁盘空间。
  • 打开文件后总数变了：文件导入建立新会话，这是预期行为；先截图保存原结果。
  • 列表少于总包数：实时页保留最近2000条；文件页读取完成后使用翻页，并检查是否启用了显示筛选。文件共多少包、筛选共匹配多少包、本页多少条会分别显示；切页不改变全文件统计。队列/驱动丢弃看资源记录。
  • 需要反馈：提供操作步骤、报错原文、当时页面截图，以及本次运行日志目录。个人原始抓包不要直接上传 GitHub。
